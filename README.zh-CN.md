# llmfs

[English](README.md) | [简体中文](README.zh-CN.md)

**一套用于 LLM 管理文件系统的协议与初始化 skill。**

llmfs 帮助 AI Agent 整理、检索和维护本地文件，所需的规则与上下文就保存在文件所在的目录中。本地协议和导航都是可见的普通文件，人和后续接手的 Agent 都能直接阅读。

目标是让一个目录在不同会话之间仍然清晰可理解：这里存放什么、去哪里查找、如何安全修改，以及哪些决定需要在对话结束后继续保留。

## 为什么使用 llmfs？

随着时间推移，工作目录会积累文档、草稿、代码、参考资料和各种决定。今天的聊天可能解释了它们之间的关系，但后续会话未必拥有这些上下文。手动命名和整理所有内容，也是一项持续的工作。

llmfs 为 Agent 提供持久保存在本地的操作协议。你可以直接描述需求，或者把新资料放入 `inbox/`；Agent 通过可见文件组织内容、维护有用的导航，并保留用户要求或任务必需的上下文。目录结构根据实际内容逐步形成，而不必预先设定一套分类体系。

它适合个人研究、写作、项目资料，以及其他需要长期保留文件及其上下文的资料集合。内容可以是任意文件类型，包括 PDF、图片、代码和数据库。协议与组织状态无需依赖隐藏目录数据库、向量库或聊天历史，也能被直接阅读和理解。

## 工作原理

项目分为两层：

- **初始化 skill**：安装或检查本地协议入口。可独立安装的包位于仓库内层的 [`llmfs/`](llmfs/) 目录。
- **文件系统协议**：指导目标目录中的后续工作。安装后，Agent 读取并遵循该目录的 `SYSTEM.md`。

新目录完成初始化后的基本结构如下：

```text
<managed-root>/
├── SYSTEM.md
├── AGENTS.md
├── LICENSE.llmfs
├── INDEX.md
└── inbox/
```

| 入口 | 用途 |
| --- | --- |
| `SYSTEM.md` | 本地操作协议，规定组织、检索、安全与维护规则。 |
| `AGENTS.md` | 引导 Agent 读取适用的 `SYSTEM.md`。 |
| `LICENSE.llmfs` | 独立保存 llmfs 许可声明，避免混入 Agent 指令。 |
| `INDEX.md` | 简述用途和范围，引导读者找到相关区域和重要入口。 |
| `inbox/` | 接收等待整理的新文件。 |

初始化 skill 安装 `SYSTEM.md`、`AGENTS.md` 和独立的 `LICENSE.llmfs` 许可声明。其余结构由 Agent 随后按照已安装的协议创建。初始化会保留已有文件；接管一个目录不会自动重组其中的内容。

核心组织结构只有 `SYSTEM.md`、`INDEX.md` 和 `inbox/`，不要求其他组织文件或通用操作流水账。

讨论和检索保持只读。讨论中形成重要、已确认且已知任务资料尚未记录的结论时，Agent 应简短提议保存一次，而不自动写入。明确授权后进入有范围的文件任务，不重复确认已有的保存授权，但必要的安全审批仍然适用。

索引提供简要定位与导航，不承载进度、操作历史或验证证据；普通内容修改不会自动触发索引更新。用户要求保存的内容和续接工作必需的上下文，应放在合适的语义文档中。持久状态是可见的，因此人也可以直接审阅和编辑。

## 快速开始

使用一个能够从 GitHub 获取文件、读取本地指令，并能在目标目录中查看和编辑文件的 AI Agent。建议使用 Git 保存可回退的版本记录，但受管目录并不强制要求使用 Git。

### 1. 打开目标目录

在 Agent 中打开你想管理的目录，或向它提供准确的目标路径。你可以从空目录开始，也可以接管已有文件的目录。

### 2. 让 Agent 完成初始化

将下面的请求粘贴给 Agent。如果尚未打开目标目录，请将“当前目录”替换为准确路径：

> 使用 https://github.com/leoluobuqi/llmfs/tree/main/llmfs 中的 llmfs skill 初始化当前目录。保留已有内容，替换协议文件前先征求确认。随后按照安装好的 SYSTEM.md 完成初始化。

确认初始化前，请核对目标目录。skill 会在初始化 Git 前询问；替换已有 `SYSTEM.md`，或在已经受管的目录中建立嵌套协议边界，也需要明确批准。

Agent 只需获取初始化包即可完成设置，无需永久安装 skill，也无需克隆完整的开发仓库。远程获取和本地文件操作取决于 Agent 的工具与权限；这一流程尚未在所有 Agent 中验证。如果无法获取远程文件，可以在本地提供完整的 `llmfs/` 包，包括 `SKILL.md`、`LICENSE` 和 `templates/`，再让 Agent 读取本地的 `SKILL.md`。

### 3. 在后续会话中使用

在受管目录中与 Agent 协作。确保它在检索信息或修改文件前读取适用的 `SYSTEM.md`；如果 Agent 不会自动加载 `AGENTS.md`，请明确要求它先读取这个入口文件。

日常请求示例：

- **整理新资料**：“处理 inbox 中的文件，将它们放到合适的区域，只在检索路线变化时更新导航。”
- **查找已有工作**：“找到我们关于发布计划的笔记，给出相关文件路径。”
- **保存决定**：“把刚才的决定保存到项目笔记中，留下足够的上下文，方便后续会话理解。”
- **维护资料**：“检查这个区域的导航是否有失效链接，并在移动已有文件前提出改进建议。”

这些是发给 Agent 的自然语言请求，不是 shell 命令。普通讨论不会自动保存。移动、删除、替换文件和对外分享，仍需遵循已安装的协议及你的授权。

### 可选：安装 skill 以便重复使用

如果你经常初始化或更新受管目录，可以按照所用 Agent 支持的 skill 安装方式，安装仓库内层的 [`llmfs/`](llmfs/) 目录。请将 [`SKILL.md`](llmfs/SKILL.md)、[`LICENSE`](llmfs/LICENSE) 和 `templates/` 保持在同一个包中。这个包可独立使用，无需获取仅用于开发的 `protocol/` 历史归档。安装路径和 skill 自动发现机制取决于所用 Agent。

## Hermes Agent 使用建议

### 避免与 llm-wiki 工作流重叠

使用 Hermes Agent 管理 llmfs 目录时，建议为该工作流禁用内置的 `llm-wiki` skill，避免两套文件组织与知识维护规则同时作用于同一目录。目录的组织、导航和维护应以本地 `SYSTEM.md` 为准。

请使用当前 Hermes 版本支持的 skill 管理方式，仅禁用 `llm-wiki`，不要禁用整个 skills 系统或删除已有内容。如果其他工作仍需要 `llm-wiki`，请分开使用两套工作流，并在支持的情况下使用独立配置档案。调整后开启新会话，确认 llmfs 任务不再加载 `llm-wiki`。这是一项工作流预防措施，不代表两者必然冲突，也不意味着禁用 skill 能提供安全隔离。

### 本地提交被跳过时

如果 Hermes 已读取适用的 `SYSTEM.md`，却仍因等待另一条明确请求而跳过协议要求的本地提交，可以补充说明已有授权。如果它尚未读取协议，应先解决协议加载问题；这项设置不能代替加载项目规则，也不能解决 Git 命令执行失败的问题。

使用 Hermes 的[配置工具](https://hermes-agent.nousresearch.com/docs/user-guide/configuration)，在所用配置档案的 `agent.coding_instructions` 中追加下面这句话，并保留已有指令：

> 如果用户已批准的当前仓库规则明确要求本地提交，应将该要求视为已有授权，不要再次询问确认。

常见配置位置：

- 默认配置档案：`~/.hermes/config.yaml`。
- 命名配置档案：`~/.hermes/profiles/<name>/config.yaml`。

[各配置档案相互独立](https://hermes-agent.nousresearch.com/docs/user-guide/profiles)。只对需要这项说明的档案进行修改；修改默认档案不会同步更新其他档案。工作流程规则仍应保存在 `SYSTEM.md` 中，不要在此重复维护。

这只是对 Hermes 编程指导的补充，不能强制执行提交。请开启新会话，检查一次普通的文件修改任务是否能在无需额外提醒的情况下完成规定的本地提交。这是可选的应对方式，不保证 Agent 一定遵守，也不是 llmfs 初始化的必需步骤。

## 检查与更新

skill 支持四种模式：

| 模式 | 范围 |
| --- | --- |
| `init` / `bootstrap` | 为新目标安装协议入口，然后交由其 `SYSTEM.md` 指导后续工作。 |
| `adopt` | 在已有目录中安装入口，同时保留已有内容。 |
| `check` | 检查初始化文件及其引导关系，不是完整的文件系统健康审计。 |
| `update-protocol` | 对比目标协议与包内模板，在获得明确替换授权后更新入口。 |

更新已安装的 skill 包，不会自动更新已有的受管目录。索引维护、链接转换和内容重组属于另外的操作。

### 让 Agent 更新已有目录

打开受管目录并粘贴下面的请求。如果它不是当前目录，请将“当前目录”替换为准确路径：

> 使用 https://github.com/leoluobuqi/llmfs/tree/main/llmfs 中的 llmfs skill，以 update-protocol 模式更新当前目录。先读取已安装的 SYSTEM.md，与包内模板比较，报告版本、差异及本地定制内容。修改前先征求我的批准。批准后按需更新协议入口和许可声明，保留无关内容，并按照更新后的 SYSTEM.md 完成验证和本地提交。

批准前请审阅拟议变更，不应静默丢弃本地定制内容。更新范围是 `SYSTEM.md`、相关的 `AGENTS.md` 引导规则和 `LICENSE.llmfs`，不包括目录内容或已有链接。如果无法获取远程文件，可以在本地提供完整的新版 `llmfs/` 包，改用其中的 `SKILL.md`。

当前 package 版本：**0.2.12**。当前已发布协议：**System Protocol v12（2026-11-12）**。发布历史见[协议版本索引](protocol/INDEX.md)。

## 边界与限制

- **依赖 Agent 遵守规则。** llmfs 提供的是书面指令，不是后台服务或强制执行引擎，不能保证 Agent 会发现并正确遵循每一条规则。
- **协议不构成安全隔离。** 它不能提供操作系统级隔离，不能阻止任意进程访问凭据，也不能代替文件权限等技术保障。
- **能访问文件不代表能理解所有内容。** 阅读 PDF、图片或其他格式可能需要额外工具。Agent 应区分实际检查过的内容与仅根据文件名作出的推测。
- **Git 支持恢复。** 它不能代替可见文档，也不会自动提供异地备份。按当前协议，在 Git 管理的根目录中，已完成并验证的文件修改任务需要完成本地任务级提交，除非用户或仓库约定另有要求。提交仅包含授权改动，并保留其他改动及其暂存状态；推送需要明确请求。
- **跨工具使用存在限制。** 普通文件让不同工具都能查看状态，但跨 Agent 的实际运行兼容性尚未确立。请使用你选择的 Agent 验证工作流程。

## 仓库结构与维护

如果要开发 llmfs 本身，可以克隆开发仓库：

```sh
git clone https://github.com/leoluobuqi/llmfs.git
```

```text
llmfs/
├── README.md
├── README.zh-CN.md
├── LICENSE
├── llmfs/                  # 可独立安装的初始化 skill
│   ├── SKILL.md
│   ├── LICENSE
│   └── templates/
│       ├── AGENTS.md
│       └── SYSTEM.md       # 当前已发布版本的安装模板
└── protocol/               # 开发草案与发布历史
    ├── INDEX.md
    ├── SYSTEM.v0.md … SYSTEM.v12.md
    └── SYSTEM.next.md      # 可修改的草案，不用于正常安装
```

后续协议修改应从 `protocol/SYSTEM.next.md` 开始。已发布的 `SYSTEM.vX.md` 快照不可修改。发布新版本、更新包内模板和版本信息前，请遵循 [protocol/INDEX.md](protocol/INDEX.md) 中的评审与发布流程。

发布 package 与更新受管目录是两个独立步骤。发布新版本不代表获得了替换任何目录中已安装 `SYSTEM.md` 的授权。
